# 面试间 3D 数字人面试官（TalkingHead）集成设计文档

> 版本：v1.0（2026-08-28）
> 范围：仅前端（`frontend/`），后端无任何改动。

## 1. 背景与目标

面试间（`InterviewRoomPage`）目前已具备：面试题 TTS 朗读（超 300 字自动分段顺序播放）、按住说话录音、ASR 转写。本次需求是引入 **TalkingHead 3D 数字人作为 AI 面试官形象**，在朗读面试题时开口说话（口型同步 + 表情/视线），提升拟真感。

### 需求确认结论（已与用户逐项确认）

| 决策点 | 结论 |
|---|---|
| 数字人角色 | AI 面试官形象，与面试题 TTS 朗读联动开口说话 |
| 形象来源 | TalkingHead 官方内置 Ready Player Me 模型，开箱即用 |
| 启用方式 | 面试间内提供开关，**默认开启**，可关闭回到纯语音模式 |

## 2. 现状分析（代码事实）

- TTS 播放链路：`InterviewRoomPage.playQuestion()` → `synthesizeSpeech(seg)`（`api/speech.ts`，后端 `/api/speech/tts` 返回音频 Blob）→ `voicePlayer.play(blob)`（`lib/voicePlayer.ts`）。
- `voicePlayer` 内部用 `HTMLAudioElement` + 自建 `AudioContext` 接 `AnalyserNode`，并暴露 `getLevel()`；多段朗读由 `speechVersionRef` 版本号做取消控制。
- 静音（`toggleMute`）会停止当前朗读并阻止后续播放；"重播"按钮可重新朗读当前题。
- 页面布局：`ir-body` 左栏摄像头预览（行为分析用 tfjs），右栏为问题卡 + 转录卡；底部 `ir-footer` 有录音按钮和 TTS 控制组（静音 / 重播）。

**关键约束**：后端 TTS 返回的是中文语音、无词级时间戳。TalkingHead 内建的文本驱动口型模块只支持 en/fi/de/fr/lt，`speakAudio` 的精确口型又依赖 `words/wtimes/wdurations` 时间戳——因此**必须走音频驱动口型**方案（见 §4）。

## 3. 技术选型

| 项 | 选择 | 说明 |
|---|---|---|
| 3D 渲染与数字人 | `@met4citizen/talkinghead` v1.7.x（MIT） | Three.js/WebGL 渲染 Ready Player Me 全身 GLB 模型，自带视线、表情、手势、口型混合变形 |
| 3D 引擎 | `three` ^0.180（peer 依赖） | TalkingHead 指定版本 |
| 音频驱动口型 | `@met4citizen/headaudio` 模块（HeadAudio，MIT） | AudioWorklet 实时 MFCC + 高斯原型分类，从**任意音频流**直接输出 Oculus viseme，不需要文本和时间戳，纯浏览器内运行 |
| 模型文件 | 官方 `brunette.glb`（Ready Player Me 制作，CC BY-NC 4.0 非商用） | **本地化到 `frontend/public/avatars/`**，不依赖外网 CDN；本项目为个人练习用途，符合非商用条款 |

已核实的关键 API（README + 源码）：`new TalkingHead(node, opts)`、`showAvatar({url, body, lipsyncLang, ...})`、`speakAudio({audio: AudioBuffer, words: [], ...})`、`speakMarker(cb)`（用回调感知队列播完）、`stopSpeaking()`、`stop()/start()`、`setView()`、`lookAtCamera()`、`setMood()`；HeadAudio 通过 `head.audioCtx.audioWorklet.addModule()` 注册、`head.audioSpeechGainNode.connect(headaudio)`、`onvalue` 回调直接写 `head.mtAvatar[key]`。

## 4. 总体架构

```
InterviewRoomPage
 ├─ playQuestion(content)          # 现有流程不动，播放环节分流
 │    └─ avatar.enabled ?
 │         ├─ 是 → AvatarController.speak(blob)      # 解码→speakAudio 入队→speakMarker 等待
 │         │        └─ HeadAudioWorklet onvalue ──→ mtAvatar[viseme]  # 实时口型
 │         └─ 否 → voicePlayer.play(blob)            # 现有纯语音路径（保留作降级）
 ├─ <InterviewerAvatar/>           # 新组件：canvas 容器 + 开关 + 加载/失败态
 └─ CSS（InterviewRoomPage.css）
```

新增/修改文件：

| 文件 | 动作 | 职责 |
|---|---|---|
| `src/lib/avatar/avatarController.ts` | 新增 | 封装 TalkingHead + HeadAudio 生命周期：`init(canvas)`、`speak(blob)`、`stop()`、`setEnabled(bool)`、`dispose()`；导出单例控制器 |
| `src/components/InterviewerAvatar.tsx` | 新增 | React 组件：canvas 挂载、加载进度、失败降级 UI、开关按钮 |
| `src/pages/InterviewRoomPage.tsx` | 修改 | `playQuestion` 播放分流；`avatarEnabled` 状态（localStorage 持久化，默认 `true`）；静音/暂停/结束/重播联动 |
| `src/pages/InterviewRoomPage.css` | 修改 | 数字人面板样式（与现有 room-card 视觉一致） |
| `frontend/public/avatars/brunette.glb` | 新增 | 本地模型文件（约十几 MB） |
| `package.json` | 修改 | 新增 `@met4citizen/talkinghead`、`three` 依赖 |

后端零改动；WPS/邮箱/ASR 等既有能力不受影响。

## 5. 详细设计

### 5.1 AvatarController（核心封装）

```ts
export interface AvatarController {
  init(canvas: HTMLCanvasElement): Promise<void>;   // WebGL 检测→new TalkingHead→showAvatar→注册 HeadAudio
  speak(blob: Blob): Promise<void>;                 // decodeAudioData → speakAudio 入队 → speakMarker 等待播完
  stop(): void;                                     // stopSpeaking()，静音/切题/断开时调用
  setEnabled(on: boolean): void;                    // 开/关面板与口型输出（关闭时恢复 idle 姿态）
  readonly available: boolean;                      // 初始化是否成功（失败则整体降级）
  dispose(): void;
}
```

要点：

- **播放等待**：`speakAudio()` 是入队即返回；播完信号用 `speakMarker(cb)` 挂在队列尾部实现，`speak()` 返回的 Promise 在整段音频结束后 resolve，与现有 `voicePlayer.play()` 的语义一致，`playQuestion` 的分段顺序播放逻辑零改动。
- **取消控制**：沿用 `speechVersionRef` 机制；版本不匹配时调 `stop()` 并放弃后续分段。
- **AudioContext 冲突规避**：数字人模式下音频统一由 TalkingHead 的 `audioCtx` 播放（`speakAudio` 走其 speech 增益节点），**不再**走 `voicePlayer` 的 `HTMLAudioElement`，避免同一媒体元素被两个 `MediaElementSource` 重复接管的问题。
- **口型链路**：`head.audioSpeechGainNode.connect(headaudio)`；`headaudio.onvalue = (key, value) => { Object.assign(head.mtAvatar[key], { newvalue: value, needsUpdate: true }) }`；`head.opt.update = headaudio.update.bind(headaudio)` 挂进渲染循环。
- **姿态细节**：`setView("head")` 取近景半身/头像视角；`lookAtCamera()` 在每段朗读开始时调用；`avatarIdle` 保持默认（待机时自然眨眼、小幅头部动作），避免"死脸"。

### 5.2 口型精度分级与降级链

```
Level 1  HeadAudio 音频驱动口型（默认）
         └─ 模型文件/Worklet 加载失败 ↓
Level 2  音量驱动简化口型：复用现有 analyser 的 getLevel()，
         写 mtAvatar["viseme_aa"]（嘴开合）
         └─ TalkingHead 本体初始化失败（无 WebGL / 模型 404）↓
Level 3  隐藏数字人面板，完全回到现有纯语音模式（当前行为）
```

降级只影响视觉效果，**语音播放永不受阻**：每次 `speak()` 前检查可用性，不可用立即回落 `voicePlayer` 路径，并在面板上显示一行"数字人不可用，已切换纯语音"。

已知限制（如实说明）：HeadAudio 的预训练 viseme 模型以英文语料为主，中文音频的口型分类精度会打折扣（元音开口度大体正确，个别音素不完全贴合）。Level 2 的音量驱动作为无中文依赖的兜底，观感更粗但绝对稳。

### 5.3 状态联动矩阵

| 场景 | 行为 |
|---|---|
| 进入面试间 | 默认开启 → 异步初始化（不阻塞连接 WebSocket）；面板显示"面试官进场中…" |
| 朗读面试题 | `speak()` 驱动口型；分段之间自然闭嘴 |
| 静音 | `stop()` 清空队列，数字人闭嘴回 idle |
| 重播 | 同朗读 |
| 暂停 / 断开 / 结束 / 卸载 | `stop()`；页面卸载时 `dispose()` 释放 WebGL 资源 |
| 用户关掉开关 | `stop()` + 隐藏 canvas（不销毁，可再开）；状态写 `localStorage`，下次进入记住选择 |
| 用户答题（录音） | 数字人保持 idle 聆听姿态，无口型 |

### 5.4 UI 设计

- 面板位置：`ir-body` 右栏顶部、问题卡上方，高约 200–240px 的圆角卡片（与 `room-card` 同风格），canvas 自适应。
- 面板右上角小开关："数字人面试官"（默认开）；关闭后卡片收起为一行细条，可再展开。
- 加载中显示进度（`showAvatar` 支持 onprogress）；失败显示降级提示。
- 摄像头预览仍保留在左栏——用户看自己、看数字人面试官，布局语义清晰。

## 6. 性能与风险

| 风险 | 评估与对策 |
|---|---|
| 中文口型精度 | 见 §5.2 降级链；视觉增强而非功能依赖，可接受 |
| 包体积 | three + talkinghead 动态 `import()` 懒加载，仅面试间路由按需拉取；模型文件仅在开启时请求且可被浏览器缓存 |
| GPU 占用 | 与左栏 tfjs 行为分析同时跑 3D 渲染；关闭开关即停渲染循环（`head.stop()`）。低端机降级路径（Level 3）兜底 |
| WebGL 不可用（无头环境/旧浏览器） | 初始化检测，直接 Level 3 降级，不影响面试 |
| 许可 | talkinghead/headaudio MIT；brunette.glb 为 CC BY-NC（非商用），个人项目合规，商用需换模型 |
