## 2. 现状分析（代码核实结论）

### 2.1 数据层已具备条件
- `backend/migrations/001_init.sql` 定义 `interview_turns` 表，字段含 `role`、`kind`、`content`、`seq`。
- `backend/internal/interview/service.go` 写盘时已区分类型（代码确认）：
  - `interviewer` + `question` → 主问题
  - `interviewer` + `follow_up` → 追问
  - `candidate` + `answer` → 候选人回答
- 追问的归属关系：当前代码为**顺序追问**，即每个主问题之后连续跟若干「追问→回答」。因此「按最近一个主问题归组」即可得到两级树，**无需新增父子字段**。
- 历史数据兼容：`kind` 标记自始存在，**老面试数据可直接生成树形，无需回填**。

### 2.2 前端现状
- `frontend/src/api/interviews.ts`：
  - `InterviewTurn` 含 `seq / role / kind / content / created_at` 等字段。
  - `Interview` 含 `turns: InterviewTurn[]`。
  - `getInterview(id)` 返回完整面试（含 turns）。
- `frontend/src/pages/InterviewDetailPage.tsx`：
  - 调用 `getInterview`，按 `seq` 排序后平铺渲染「对话记录」卡片（`transcript-turn` 样式）。
- `frontend/src/pages/ReportPage.tsx`：
  - 调用 `getReport(id)` 获取评分反馈（四维评分/亮点/改进/建议/表达分析/行为信号），**当前不含 turns**；要展示追问链需再调 `getInterview(id)`。

## 3. 方案设计

### 3.1 树形构建（前端纯函数，可单元测试）
新增 `frontend/src/lib/followUpTree.ts`：

- 输入：按 `seq` 升序的 `InterviewTurn[]`
- 输出：树节点数组 `FollowUpNode[]`
- 节点类型：`main`（主问题）/ `follow`（追问）/ `answer`（回答）
- 构建规则：
  1. `role=interviewer && kind=question` → 新建 `main` 节点挂到根；
  2. `role=interviewer && kind=follow_up` → 新建 `follow` 节点，挂到当前 `main` 下（两级）；
  3. `role=candidate && kind=answer` → 挂到**最近一次提问**（主问题或追问）之下；
  4. 异常容忍：无追问的场次退化为「主问题→回答」列表；进行中/中断场次按已有时序容错，不抛错。

### 3.2 渲染组件（复用）
新增 `frontend/src/components/FollowUpTree.tsx`：

- `main` 节点：主问题标题 + 展开/收起控制（默认展开）；
- `follow` 节点：缩进一层，标记「追问」；
- `answer` 节点：跟随其提问节点、相同缩进，样式区分「我」；
- 样式写入现有 `InterviewPages.css`（详情页）与报告页样式文件，保持现有设计语言。

### 3.3 面试详情页改造
- `frontend/src/pages/InterviewDetailPage.tsx`：
  - 将现有平铺「对话记录」渲染替换为 `<FollowUpTree turns={...} />`；
  - 数据来源不变（`getInterview`），**后端零改动**。

### 3.4 报告页
- **不改动**（按用户最新确认）。`ReportPage.tsx` 维持现状，不新增追问链卡片，也不额外拉取 turns。

### 3.5 明确不改动项
- 数据库：不新增表/字段/迁移。
- 后端：不改任何接口与逻辑（`getInterview` 已够用）。
